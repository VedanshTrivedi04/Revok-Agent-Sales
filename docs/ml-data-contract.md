# ML data contract (churn + expansion)

Generated by `scripts/export_template.py` from `revops_ai/ml/specs.py`. To train on REAL data, export one CSV per
task with these columns and run `uv run python scripts/train_model.py --task <churn|expansion> --csv <file>`.
Use `--validate-only` first: it prints errors (blocking) and warnings (informational).

**One row = one renewal event.** All features are measured at a snapshot **90 days before the renewal date**
(never use data from after the snapshot: it would leak the answer). The label is observed afterwards.

Rules: at least 500 rows, >= 50 positives and >= 50 negatives; dates should span > 1 year (validation is time-based:
oldest 60% train, next 12% early-stopping, 14% calibration, newest 14% test). Unknown categories become missing.

## Task `churn` - Churn / downgrade risk

Target `churned_or_downgraded`: 1 if the customer churned or downgraded at (or within the window after) this renewal, else 0.

| `renewal_date` | date | yes | - | Renewal date |

| `arr` | num | yes | 0.. | Annual recurring revenue of the account (currency units) |
| `seats_purchased` | int | no | 0.. | Seats on the contract |

| `contract_months` | int | no | 1..120 | Contract length in months |
| `discount_pct_last_renewal` | num | no | 0..100 | Discount given at the last renewal, percent |
| `usage_change_pct` | num | yes | -100.. | Active users: last full week vs the 4 weeks before it, percent |
| `usage_slope_4w` | num | no |  | Active-user change per week over 4 weeks |
| `usage_slope_12w` | num | no |  | Active-user change per week over 12 weeks |
| `usage_volatility` | num | no | 0.. | Std/mean of weekly active users over 12 weeks |
| `seat_util` | num | yes | 0..3 | Seats used / seats purchased in the last week |
| `days_since_meeting` | num | yes | 0.. | Days since the last customer meeting |
| `meetings_90d` | int | no | 0.. | Customer meetings in the last 90 days |
| `days_since_reply` | num | no | 0.. | Days since the customer last replied to an email |
| `unanswered_outbound` | int | no | 0.. | Our emails (last 21 days) with no customer reply |
| `active_contacts_90d` | int | yes | 0.. | Distinct customer contacts active in 90 days |
| `champion_changed` | bin | yes | 0..1 | 1 if the main champion left/changed in the last 180 days |
| `champion_silent_days` | num | no | 0.. | Days since the champion last wrote |
| `neg_sentiment_30d` | int | no | 0.. | Negative-sentiment signals extracted from emails, last 30 days |
| `competitor_30d` | int | no | 0.. | Competitor mentions, last 30 days |

| `escalation_30d` | int | no | 0.. | Escalations, last 30 days |

| `upgrade_intent_30d` | int | no | 0.. | Upgrade-intent signals, last 30 days |

| `nps_score` | num | no | -100..100 | Latest NPS/CSAT-style score of the account, -100..100 (often missing) |
| `payment_failures_90d` | int | no | 0.. | Failed payments in the last 90 days |
| `renewal_deal_has_next_step` | bin | no | 0..1 | 1 if the open renewal deal has a next step (missing if there is no renewal deal) |
| `renewal_deal_days_in_stage` | num | no | 0.. | Days the open renewal deal has been in its current stage (missing if no deal) |
| `has_usage_data` | bin | no | 0..1 | 1 if product usage is connected for this account |
| `has_email_data` | bin | no | 0..1 | 1 if email/calendar is connected for this account |
| `segment` | cat | yes | smb, mid | Customer segment |
| `plan` | cat | yes | Team, Business, Enterprise | Plan name |
| `industry` | cat | no | saas, fintech, health, retail, education, other | Customer industry |
| `region` | cat | no | na, emea, apac, in | Customer region |
| `billing_cycle` | cat | no | annual, monthly | Billing cycle |
| `crm_health` | cat | no | Green, Yellow, Red | Health value typed by the CSM in the CRM (weak signal by design) |

- Features are measured 90 days before the renewal date (point-in-time).
